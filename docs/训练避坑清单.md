## 一、必守的不变量（改坏了 sim2real 就废了）

| 不变量 | 说明 |
|---|---|
| 观测 61 维 | 48 维本体感知 + 13 维指令 `[twist(3), head_pose(4), body_pose(6)]`。**不用的指令槽位要补零，不能删。**删了就和别的策略不通用，真机没法热切换。 |
| 动作 14 维 | 14 个舵机的关节位置目标。 |
| 关节布局 | 0–4 左腿（hip_yaw, hip_roll, hip_pitch, knee, ankle）、5–8 脖子/头（neck_pitch, head_pitch, head_yaw, head_roll）、9–13 右腿。**滚轮/间隙模型上被动关节会穿插，永远不要硬编码关节索引**，用 `mdp.py` 里的 `_servo_joint_ids` / `_servo_joint_pos`。 |
| 未驱动关节 | 一律叫 `passive_*`。所有选择器用 `^(?!passive_).*`。 |
| 观测归一化 | 训练时开启 → **归一化器必须烤进 ONNX**。只能用 `scripts/export.py` 导出。手搓 checkpoint 转 ONNX，真机上策略看到的是未归一化的观测。 |
| 策略不加滤波 | 训练里没有 action low-pass。要加必须同时加运行时开关 + 迁移测试，否则训练/部署不一致直接毁掉迁移。 |
| 域随机化不累积 | mjlab 1.3.0 的 `dr.*`（`operation="add"/"scale"`）本身不累积；**自己写的 DR 函数必须"先还原再施加"**。一个会累积质心偏移的随机器曾经让所有长训烂了几个月。 |

## 二、奖励函数

### 符号约定（搞反过四次环境）
- mjlab 自带的 cost 函数返回 **≥ 0** → 权重取**负**。
- microduck 自己写的 `*_penalty` / `*_l1` 返回 **≤ 0** → 权重取**正**。
- 给自取负的惩罚函数配负权重 = 双重取负 = 奖励违规行为。策略会去刷分（撅屁股跳、崩溃式坐下）。
- **万能检查：每次跑，wandb 里每个 `Episode_Reward/<penalty>` 必须 ≤ 0。**

### RL 优化的是奖励的字面意思
- 每一个没说清楚的自由度都会被利用：甩鞭子代替翻滚、侧滚代替前滚、头顶三角架代替站立。
- **把"什么算这个动作"编码成硬性的状态门控**（支撑接触、姿态轴检查、latch），而不是用小幅度的惩罚去暗示。

### 不要有"彩票"
- 任何"到达 X 就给分"的奖励必须**限速或用斜坡过渡**。提前到达目标状态然后每步领钱 = 送钱让策略买暴力。
- 指令式转换要跟踪一个**匀速变化**的内部目标（constant-rate blend）：跑在坡道前面给 0 分，所以"慢"才是最优解。只靠速度上限惩罚积分出来是有界的，会输给策略。

### 不要给正向奖励加"坏状态"门槛
- 摔倒了/趴着还给正奖励 → 策略会挑最便宜的姿势刷分。
- 用 potential-based shaping（付 Δ进度），比如付 Δcos(tilt)：上升有钱，保持是 0，刷不出来。

### 其它
- **多因子目标状态用乘积而不是加和**：加和会出现"每项都拿 80%"的折中盆地；乘积高斯只要任何一项不合格就塌掉 —— 但 std 要放宽到当前策略明显能拿到的程度，否则梯度看不见。
- **关节顶在硬限位**：加 qpos 侧的接近限位惩罚。stock `dof_pos_limits` 只在最后 ~7.5% 行程才触发；命令侧的惩罚没用（宽 ctrlrange 是故意的 —— 低 kp 舵机需要超调）。
- **正则项分两类**：动作阻断类（body_ang_vel, angular_momentum, pose std）会挡掉动态动作本身 —— 动态任务保持 LOW；平滑类（action_rate, joint_torque_rate）只是压抖动，安全可加权，但**要在技能被发现之后再加**（curriculum 从 ~0 开始）。技能还在探索阶段就上税，"什么都不做"会赢。
- **抄正则项要比 reward 质量，不是比权重**：PPO 看到的是相对优势，同样的 action_rate 权重在 4 倍大的正向任务堆下就弱 4 倍。

### 指令通道
- **一个从来没非零过的指令输入，它的权重永远是死的。** 每个指令槽位从第 0 步起就保持小的非零采样范围（哪怕权重是 0）。
- **零指令行为必须显式训练**（精确采样的 `zero_command_prob`）：均匀采样几乎永远采不到全零指令，而全零恰恰是部署时的空闲状态。
- 罕见但重要的指令区域要**显式分桶** —— 比如原地转向，独立均匀采样让转身只占 2% 经验，永远训不出来。

## 三、Curriculum

- 步数 = `iteration × 24`（`NUM_STEPS_PER_ENV = 24`）。
- `microduck_mdp.reward_weight` 用来做权重调度，**它是阶跃函数不是插值** —— 斜坡要离散成分段。
- **改 term 配置要通过 manager**（`env.event_manager.get_term_cfg(...)`），**永远不要直接改 `env.cfg.events[...]`** —— manager 在 init 时深拷贝了配置，直接改 `env.cfg` 是静默无效的（这个坑也咬过 eval 脚本）。
- **每个阶段都要对齐"策略实际已经学会的东西"**：当前这一段还没巩固就不要加难度；技能还没出现就不要上税。如果 wandb 指标在某个 curriculum 边界**正好下跌**，说明节奏错了 —— 拉长阶段或把引入点往后推，**绝不往前推**。
- **反向 curriculum**（从动作中途开始 episode，包括接近完成的状态）是"学会了开头、最后一步学不会"的可靠解法 —— 否则 frontier 拿不到 on-policy 数据。

## 四、训练运维

- wandb project: `mjlab_microduck`；日志在 `logs/<experiment_name>/`。
- 断点续训：`--agent.load-checkpoint model_XXXX.pt --agent.resume True`。
- **warm start ≠ resume。** mjlab 的 runner 把 `common_step_counter` 存进 checkpoint 并在 load 时恢复（连同 iteration），所以加载别的任务的 checkpoint 会让所有基于步数的 curriculum 在 iteration 1 就跳到最终阶段。跨任务 warm-start 要加 `MICRODUCK_WARM_START=1` 前缀，把步数重置到 0，同时保留权重/归一化器/优化器。**而且只能用归一化器兼容的任务互相 warm-start**（站立专家的 twist std 是 0.005，绝不能拿它去初始化走路环境）。
- **watch 哪些指标**：mean reward 在涨 **且** episode 长度符合任务预期；每个惩罚项 ≤ 0；**主任务项本身在涨**（总 reward 可能光靠正则项就涨了，而把戏根本没发生）。
- **预算**：简单的一次性把戏 ≈ 1000 iters @ 4096 envs；步态和 curriculum 重的恢复任务要 4000–6000。
- **失败先测量再 theorize。** 跑之前先做无头评估（按 spawn 类型的分项统计、结束状态聚类、角速度曲线），再改奖励。上游的"失败"里有好几个其实是早期 checkpoint、成功判据把一个行为簇劈成两半、以及一个 pay cap 在和真实物理对着干。
- **看视频，别只看数字。** sim 指标过了但视频过不了人眼是常事 —— 要看是哪个 geom / 哪个轴在接触。
- **汇报实际 rollout 表现**（"会滚，但 1/3 概率脸着地"），不要只说"成功了！"。好不好由用户判断。

## 五、Sim2real 陷阱

- **一次干净的 `uv sync` 是基准线**（HF Jobs 跑的就是这个）：任何靠手工装本地包才能跑通的东西，远程一定死。`pyproject.toml` 必须诚实。
- **物理要对齐**：25cm 的机器人**自然就会以 3.5–5.5 rad/s 翻滚** —— 不要用人类尺度的速度直觉去卡上限。要限制的是冲击和抽搐（`|a_z|`、action_rate、支撑门控），不是转速。
- **IMU 域随机化是零中心的** —— 它训练的是对"安装偏差大小"的容忍，**没法补偿系统性的安装偏置**（那是运行时标定的事）。
- 真机部署是热切换 ONNX（walk / stand / trick），共用一套观测契约 —— 上真机前先用 `scripts/infer_policy.py` 演练，**注意指令槽位要写对**：posture flag 住在 twist 的 vx 槽位；喂全零 = "站立"，看起来就像"策略不理按钮"。
- **phases 驱动的动作**（ground pick）和 **posture flag 驱动的动作**（sit/stand）由 daemon 自己驱动，不属于可发布的一键技能。

## 六、ONNX 导出（最容易出错的一步）

- **只能用 `scripts/export.py`**（或 `uv run publish`），它把观测归一化器烤进图里。
- 形状必须严格是 **`[1,61] -> [1,14]`**，否则 `publish` 拒绝。
- 导出后自检：跑一遍"合理输入"，拒绝 NaN 或常数输出。
- `uv run publish` 会自动填 `training` 区块（task / commit / branch / dirty / run / checkpoint）。
- 2026-10-27 之后导出的 ONNX 自带 provenance 元数据（`run_path`、`task_id`、`checkpoint`、`checkpoint_sha256`），读法：`onnx.load(f).metadata_props`。
