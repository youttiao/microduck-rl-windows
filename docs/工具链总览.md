# MicroDuck 训练工具链总览

从机器人本体一路讲到训练脚本，回答"这东西到底是怎么串起来的"。

---

## 一、一句话版本

**在 GPU 上用 MuJoCo Warp 跑物理仿真、用 PPO 训练一个 61→14 的小神经网络，把这个网络导出成 ONNX，再塞进机器人上那个 50 Hz 的 Rust 实时循环里。** 仿真里练出来的动作就是真机上跑的动作 —— 这就是所谓 sim2real。

```
训练机 (Windows + RTX 5080)                      鸭子本体 (RK3566)
┌──────────────────────────────────────┐         ┌────────────────────────┐
│  MJCF 机器人模型 + BAM 舵机模型      │         │  robotd (Rust)         │
│         ↓ MuJoCo Warp (GPU 物理)    │  ONNX   │   50 Hz 控制循环        │
│  4096 个并行环境                      │ ──────► │   电机总线 (UART)       │
│         ↓ rsl_rl (PPO)               │ 61→14   │   IMU / 相机 / ToF      │
│  观测归一化 + 域随机化               │         │   策略热切换 (walk/     │
│         ↓                            │         │    stand/trick)        │
│  model_N.pt ──► scripts/export.py    │         └────────────────────────┘
│                   ↓ ONNX (归一化烤进图)│
└──────────────────────────────────────┘
```

## 二、分层拆解

### 第 1 层：机器人本体（硬件）

| 项 | 值 |
|---|---|
| 尺寸 / 重量 | 约 25 cm 高，800 g |
| 电机 | 产品页写 15 个；RL 里 **14 个受控舵机**（Dynamixel XL330） |
| 关节布局 | 0–4 左腿（hip_yaw, hip_roll, hip_pitch, knee, ankle）／5–8 脖子+头（neck_pitch, head_pitch, head_yaw, head_roll）／9–13 右腿 |
| 传感器 | 摄像头、ToF 深度（头）、两个 IMU（身体 + 头）、NFC |
| 主控 | Rockchip RK3566，Linux |
| 控制频率 | **50 Hz**（物理步长 0.005 s，环境步长 0.02 s） |

### 第 2 层：真机运行时（Rust 仓库 `pollen-robotics/microduck`）

- `robotd` 是**唯一**拥有电机总线的进程，50 Hz 跑控制循环；其它 daemon（相机、蓝牙、手柄、NFC、升级器）通过 Unix socket 上的 JSON-RPC 跟它说话。
- `robotctl` 是运维 CLI：`monitor`（实时看关节/IMU/电量/是否摔倒）、`configure`（改配置）、`policy load/add/reset`（装策略）、`pad bind`（绑按键）。
- **策略是运行时可热切换的**：走路 / 站立 / 把戏各有槽位，机器人随时能从"走"切到"翻跟头"，因为它们**共享同一套观测契约**。
- 完整手册在仓库的 `docs/robot/cheatsheet.md`。

### 第 3 层：策略的契约（最容易踩坑的一层）

训练出来的东西是一个 ONNX 图，形状**固定**：

```
输入  obs      [1, 61]   ← 48 维本体感知 + 13 维指令
输出  actions  [1, 14]   ← 14 个关节的位置目标
```

61 维的构成（从冒烟测试的实际输出里核对过）：

| 段 | 维度 | 内容 |
|---|---|---|
| `base_ang_vel` | 3 | 陀螺仪 |
| `projected_gravity` | 3 | 投影重力（等价于"倾斜了多少"） |
| `joint_pos` | 14 | 关节角（相对默认姿态） |
| `joint_vel` | 14 | 关节角速度（滞后 1 个控制步，模拟 XL330 固件） |
| `actions` | 14 | 上一步的动作 |
| `command` | 3 | `twist`：速度指令（vx, vy, vyaw） |
| `head_command` | 4 | 头部 4 个关节相对默认姿态的目标（弧度） |
| `body_command` | 6 | 身体 6 维姿态目标（x,y,z,roll,pitch,yaw） |

> **指令槽位是定死的 13 个。** 现有任务只用了 `twist[0]`、`twist[1]`、`twist[2]`、`head[0..3]` 里的 `twist[0]` 和 head 四个。**`body` 那 6 个和 `twist[1]/twist[2]` 是空的 —— 新动作要占一个空槽位。**

**归一化必须烤进 ONNX。** 训练时开了观测归一化（`EmpiricalNormalization`），如果不烤进去，真机上策略看到的是没归一化的数，行为完全不同。所以**只能用 `scripts/export.py` 导出**，不能手搓 checkpoint 转 ONNX。

> 实测：本机导出的图是 9 个节点（`Sub`+`Div` = 归一化器，`Gemm`×4 + `Elu`×3 = 61→512→256→128→14），和官方发布的策略**逐节点一致**。

### 第 4 层：训练栈（Python 仓库 `pollen-robotics/microduck_rl`）

| 组件 | 版本 | 干什么的 |
|---|---|---|
| **mjlab** | 1.3.0 | 框架。抄 Isaac Lab 的 API（`ManagerBasedRlEnv`、event/reward/curriculum/termination manager），但物理引擎换成 MuJoCo Warp |
| **MuJoCo Warp** | 3.8.1 | GPU 物理引擎。MuJoCo 的 CUDA 重写，跑在 NVIDIA Warp 上，一帧几千个并行世界 |
| **mujoco** | 3.10.0 | MJCF 模型解析 + CPU 端渲染 |
| **warp-lang** | 1.12.0 | NVIDIA 的 GPU kernel 框架。**自带 CUDA 12.9 运行时** |
| **rsl-rl** | 5.0.1 | PPO 实现（actor/critic、观测归一化、课程） |
| **torch** | 2.9.1 | 网络前向/反向 |
| **BAM** | git | Better Actuator Models。**XL330 的电压控制律模型**：反电动势、库仑+Stribeck 摩擦、负载相关摩擦、堵转扭矩、齿隙 |

> **BAM 是这套东西 sim2real 的关键。** 25cm、800g 的小机器人，14 个微型舵机驱动 —— 舵机保真度就是 sim2real 差距的主要来源。所以它不建模理想 PD，而是建模 XL330 的真实电压控制律。实测启动日志：`model='m6' joints=14 kt=0.3660 R=2.8114 vin=range=(6.5, 8.2) force_limit=±1.07Nm`。

### 第 5 层：仿真里到底在模拟什么

`src/mjlab_microduck/` 下面：

- `robot/microduck/*.xml` —— MJCF 模型，从 Onshape 用 `onshape-to-robot` 导出。三套碰撞模型：`robot_walk.xml`（只有脚会碰地，摔了不贵）、`robot_groundcontact.xml`（身体也能躺地上，给恢复类任务用）、`robot_groundcontact_rollers.xml`（带轮子）。
- `tasks/microduck_*_env_cfg.py` —— **一个任务一个文件**（走路、站立、坐下、踢、翻跟头、溜冰…），共 18 个基础任务 + 15 个 `-Backlash-` 变体。
- `actuator/friction_dr_bam.py` —— BAM + 摩擦域随机化 + 齿隙编码器反馈。
- `tasks/mdp.py` —— 所有自定义的奖励函数、event、观测、curriculum。

**域随机化**（每次 reset 重采样）：质心偏移、头部质心、质量/惯量、电机 kp/kd、关节摩擦、惯量臂、IMU 安装角偏差、编码器零偏、电压范围与压降、指令延迟、推挤扰动。

**齿隙（Backlash）变体**：每个舵机串联一个 ±1° 的齿轮间隙关节。因为真机的编码器在间隙输出侧，所以观测和固件 PD 都必须"穿过"间隙读。

### 第 6 层：资产与分发（Hugging Face Hub）

| 仓库 | 内容 |
|---|---|
| `pollen-robotics/microduck-policies` | 官方 10 个 ONNX 策略 + `manifest.json`（schema 2）。机器人出厂跑的就是这一套 |
| `pollen-robotics/microduck-training` | 9 个训练包（完整 rsl_rl checkpoint + wandb 配置 + provenance）。可以 warm-start |
| `pollen-robotics/microduck-arena` | 竞技场（HF Space）：6 个挑战，每个挑战一个训练环境 + 评测规则 |

**manifest.json** 决定一个 ONNX 怎么被机器人加载：`kind`（episodic / perpetual / scripted）、`slot`（walk / stand / sitstand / ground_pick / kick_left / kick_right / roulade）、`duration_s`、`command.encoding`（constant / phase / posture_flag）。装的时候 `robotctl policy add <名字> <仓库>`。

### 第 7 层：工具链

| 工具 | 用途 |
|---|---|
| **uv** | Python 依赖 + 虚拟环境。`uv.lock` 锁死一切版本 |
| **wandb** / **tensorboard** | 训练曲线。默认 wandb（要账号），本地可以用 tensorboard |
| **onnxruntime** | 导出后的验证 / CPU 推理 |

## 三、一次完整训练的流水

```bash
# 0) 冒烟测试 —— 上游 AGENTS.md 反复强调：长跑之前必做，能以极低成本抓到 ~95% 的配置错误
uv run train Mjlab-Velocity-Flat-MicroDuck --env.scene.num-envs 64 --agent.max_iterations 5

# 1) 正式训练 —— 4096 个并行环境，约 1-2 小时出可用步态
uv run train Mjlab-Velocity-Flat-MicroDuck --env.scene.num-envs 4096

# 2) 看曲线 —— 每个 Episode_Reward/<penalty> 必须 ≤ 0，主任务项本身必须在涨
#    （总 reward 涨可能只是正则项在涨，把戏根本没发生）

# 3) 导出 ONNX —— 必须走这个脚本，它把归一化烤进图里
uv run scripts/export.py Mjlab-Velocity-Flat-MicroDuck --wandb-run-path <entity/project/run>

# 4) 在模拟器里看视频 —— sim 指标过了但视频过不了人眼是常事
uv run play Mjlab-Velocity-Flat-MicroDuck --wandb-run-path <...>

# 5) 装到真机
sudo robotctl policy load walk /home/microduck/my_walking.onnx
```

## 四、几个反直觉的点

1. **策略不负责计时。** 让策略自己数拍子做坐下-站起，十次全挂 —— PPO 的探索噪声几秒内就把关节里的时钟冲垮了。**节奏由指令/时间轴负责，策略只管执行。**
2. **新动作要占一个指令槽位**，不是改观测布局（观测布局一变，所有策略就不能热切换了）。
3. **奖励函数的符号约定搞反过四次环境。** mjlab 自带的 cost 函数返回 ≥ 0 → 权重取负；microduck 自己写的 `*_penalty` 返回 ≤ 0 → 权重取正。搞反了就把惩罚变成奖励，策略会专门去刷分。**万能检查：wandb 里每个 `Episode_Reward/<penalty>` 必须 ≤ 0。**
4. **25cm 的机器人自然就会以 3.5–5.5 rad/s 翻滚。** 不要用人类尺度的速度直觉去卡上限，要限制的是冲击和抽搐（`|a_z|`、action_rate、支撑门控），不是转速。
5. **最好的 checkpoint 经常不是最后一个。** 上游的参考策略是按"每个 checkpoint 都在竞技场的规则下打过分"选出来的，不是按训练曲线。
6. **上真机前先在模拟器里演练指令槽位。** posture flag 住在 `twist` 的 vx 槽位；喂全零 = "站立"，看起来就像"策略不理按钮"。
